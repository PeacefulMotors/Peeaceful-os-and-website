## Availability fix

Root cause: `app_data.booking_windows` phase 2 (from 2026-08-24) listed weekdays as "Evening 6:00-8:30" only, the old page used a native date input so closed days were pickable, and availability v2 defaulted to a 200-day range that Google freeBusy rejects.

New phase from 2026-10-04 (owner Sep 11 spec, confirmed 4 Oct):

- Mon to Fri: Morning 8:30-11:00, Midday 11:00-1:30, Afternoon 2:00-5:30.
- Saturday: Morning 8:00-10:30, Midday 11:00-1:30, Afternoon 2:00-4:30.
- Sunday: closed.
- Evening 6:00-8:30 only on dates listed in `evening_open_dates` (weekdays).
- `closed_dates` removes all windows for listed dates.
- `known_blocks`: Parts pickup Mon to Fri 08:00-08:45.
- Times are America/Chicago. Default range 90 days, maximum 92.

Availability still fails closed when the calendar cannot be verified, and the page shows "Availability cannot currently be verified".

## Payment return fix

The booking-hold Payment Link success_url is `https://xsqjskbcmsjzkumbsrti.supabase.co/functions/v1/booking-page?paid=1`. The Supabase gateway serves function HTML as text/plain, so customers saw raw HTML. booking-page v17 now returns a 302 to `https://peacefulmotors.com/booking/confirmed`, which looks up hold status server-side through the Worker (`/api/booking-status`). URL parameters are display hints only. Paid state comes only from the signed Stripe webhook.

Recommended owner change (Stripe dashboard): set the Payment Link after-completion redirect to `https://peacefulmotors.com/booking/confirmed?session_id={CHECKOUT_SESSION_ID}`.
